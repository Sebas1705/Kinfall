# Android tester distribution (Firebase App Distribution)

How the Kinfall Android app (`apps/mobile`, application id `es.sebas1705.kinfall`) is built, signed and sent to testers. Why it works this way: [ADR 0002](adr/0002-kinfall-name-and-tester-distribution.md). What only the owner can do: [owner-steps.md](owner-steps.md).

Tester builds go **only** through Firebase App Distribution. The APK embeds no secret (the app has no backend, token or API key), but it is still never attached to a GitHub Release or shared elsewhere: one channel, one list of testers.

## Pipeline

```text
git HEAD ──> scripts/distribute-android.sh
               │ doppler run -p kinfall -c prd   (secrets exist only in this process tree)
               ├─ decode the keystore to a temporary folder (deleted on exit)
               ├─ npx expo prebuild --platform android      (android/ is generated, git-ignored;
               │                                             apps/mobile/package.json is restored)
               ├─ ./gradlew assembleRelease -PrequireReleaseSigning=true -PappVersionCode=<n>
               ├─ apksigner verify: refuse an APK signed with the debug key
               ├─ copy to apps/mobile/android/kinfall-<versionName>-<versionCode>.apk + .sha256
               └─ firebase appdistribution:distribute --app $FIREBASE_APP_ID --groups testers
                    (as the CI service account; release notes from git log)
```

Run it from the repository root (Git Bash on Windows, any shell elsewhere):

```sh
export JAVA_HOME=...           # JDK 17+ (21 is used here)
export ANDROID_HOME=...        # SDK with platform 36/37, build-tools 37 and NDK 27.1.12297006
scripts/distribute-android.sh --dry-run    # build, sign, verify; uploads nothing
scripts/distribute-android.sh              # the same, then uploads to group testers
```

Options: `--config <doppler config>` (default `prd`), `--groups a,b` (default `testers`), `--notes "text"` (default: commit subjects since the previous tag, or the last 15 commits when there is no tag, after a header with the version, version code and commit; when `HEAD` itself carries a tag, as in a tag-triggered CI run, the notes start at the tag before it). The script needs `doppler` (logged in, or `DOPPLER_TOKEN` set), Node and npm, and installs nothing.

### First release

`0.1.0` (versionCode 108, commit `9b6d2ce`) was uploaded on 2026-11-19 to group `testers` by this script, as the service account. The APK is 131,669,131 bytes (about 126 MiB): four ABIs and native libraries stored uncompressed (`expo.useLegacyPackaging=false`, so Android can map them without extracting), which is what makes it large; a Play AAB would be split per device. Before the upload the same build was installed on the Android emulator (AVD `webgames_api36`, API 36): it started without Metro, showed the title in English and Spanish, played into a battle, resumed the same battle (same HP) after a force stop through **Continue run**, followed the system dark mode, and `kinfall://selftest` printed `[selftest] PASS battle 3/3 run 6/6` on Hermes (bytecode 99).

### What the build contains

- The **release** variant: JavaScript bundled and minified into the APK with Hermes bytecode, so it starts without Metro or a computer. R8 minification is on (`android.enableMinifyInReleaseBuilds=true` from the Expo template).
- Native code for `armeabi-v7a`, `arm64-v8a`, `x86` and `x86_64` (the Expo template's default `reactNativeArchitectures`), so it installs on phones, tablets and emulators. One universal APK, no splits.
- Dev tools: the **Dev tools** link on the title screen exists only when `__DEV__` is true, so a release build has no link to the hello screen, the gallery or the sample-save and damage-save buttons; the app has no navigation `linking` config, so no URL opens them either. The **self test** stays reachable on purpose through `kinfall://selftest` (or `?selftest=1`), which opens it and runs it: it only reads the golden files bundled in the app and writes nothing, so it is harmless, and it is how determinism is checked on a real phone's Hermes.
- `expo-system-ui` (SDK 58 version, plugin in `app.json`), so the app's light or dark theme follows the system in native builds (`userInterfaceStyle: automatic`).

### Config plugins (generated project)

`android/` is generated by `expo prebuild` and never committed, so the native changes live in two config plugins (plus `expo-system-ui`'s own) in `apps/mobile/plugins/`:

- `withReleaseSigning.js` adds a `release` signing config read from environment variables (or Gradle properties with the same names): `ANDROID_SIGNING_STORE_FILE`, `SIGNING_STORE_PASSWORD`, `SIGNING_KEY_ALIAS`, `SIGNING_KEY_PASSWORD`. With all four set, `release` is signed with the upload key; with `-PrequireReleaseSigning=true` and one missing, the build fails; otherwise it falls back to the debug key with a warning (local release checks on an emulator only). It also reads the version code from `-PappVersionCode`.
- `withWindowsCmakePaths.js` (Windows hosts only) keeps native build paths under Windows' 260-character limit. CMake names object files after the full source path, so Skia's `cpp/` sources and the React Native codegen files that the app module compiles (`.../CMakeFiles/react_codegen_safeareacontext.dir/C_/Users/.../node_modules/react-native-safe-area-context/android/build/generated/source/codegen/...`) fail with ninja's "Filename longer than 260 characters" or `mkdir(...): No such file or directory` from a repository a few folders deep. Enabling long paths needs an administrator, so the plugin passes `-DCMAKE_OBJECT_PATH_MAX=250` to every native module (CMake then replaces the long source folder part of an object name with a hash) and moves each module's CMake folder (`.cxx`) to `<user home>/.cxx/<hash>` (or `ANDROID_CXX_STAGING_DIR`) so the folder itself is short enough. Linux and macOS (CI) are unaffected. Delete `~/.cxx` to reclaim the space.

## Versioning

- **versionName** is `expo.version` in `apps/mobile/app.json` (`0.3.0` now, the console layout release candidate; not tagged). Bump it by hand for a user-visible change, SemVer while 0.x (breaking or notable is minor, fixes are patch). A tag `vX.Y.Z` on the commit that was distributed marks a release and becomes the start of the next release notes; once the remote exists, pushing such a tag is what distributes it (see [GitHub Actions](#github-actions-automatic-on-version-tags)).
- **versionCode** is the number of commits on `HEAD` (`git rev-list --count HEAD`), passed as `-PappVersionCode`. It grows with every commit, so a later build always updates an earlier one. It needs the full history: the script refuses a shallow clone, and the workflow checks out with `fetch-depth: 0`. A local Gradle build without the property uses `android.versionCode` from `app.json` (1).
- Never distribute two different builds with the same versionCode: commit first (the notes header says `(uncommitted changes)` when the tree is dirty).

## Secrets layout (names only)

Doppler project **`kinfall`**, config **`prd`** (the project also has the default `dev`, `dev_personal` and `stg` configs, unused for now):

| Secret | What it is |
|---|---|
| `SIGNING_KEYSTORE_BASE64` | The upload keystore (PKCS12), base64 |
| `SIGNING_STORE_PASSWORD` | Keystore password |
| `SIGNING_KEY_PASSWORD` | Key password (same as the store password: PKCS12) |
| `SIGNING_KEY_ALIAS` | Key alias |
| `FIREBASE_APP_ID` | Firebase Android app id of `es.sebas1705.kinfall` |
| `FIREBASE_PROJECT_ID` | `kinfall-sebas1705` |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | JSON key of the CI service account `kinfall-ci@kinfall-sebas1705.iam.gserviceaccount.com` |

Nothing of this is in the repository, in `android/` or in the APK. The script decodes the keystore and the service account key into a temporary folder that is removed when it exits, and never prints a value.

- **Keystore file:** `D:\AndroidKeys\kinfall-release.jks` on the development PC (outside the repository), alias in Doppler. Certificate fingerprints (public, also registered in the Firebase app): SHA-1 `17:3F:2F:FD:62:5E:7F:F4:39:D2:D4:31:95:71:D9:A5:C5:11:B4:EB`, SHA-256 `EF:4C:5F:63:D0:BA:03:9A:C0:E9:D8:3C:3D:4F:57:25:6B:3F:BC:F6:20:81:12:99:1F:F5:82:65:C9:B8:FE:B9`.
- **Back it up.** Keep a copy of the keystore and its password outside this PC (a password manager entry with the file attached is enough; Doppler already holds both, so Doppler is the second copy). **Losing the key means a new key, and every tester must uninstall Kinfall and install it again** (Android refuses an update signed with another key; local saves are lost with the uninstall). If the app later goes to Google Play with Play App Signing, this key becomes the upload key and can be reset through Play support.
- **Service account:** `kinfall-ci` has one role, Firebase App Distribution Admin (`roles/firebaseappdistro.admin`), on project `kinfall-sebas1705`, and one user-managed key. To rotate it: create a new key, store it in `FIREBASE_SERVICE_ACCOUNT_JSON`, delete the old key in Google Cloud console > IAM > Service accounts.

## Firebase

- Project `kinfall-sebas1705` (display name Kinfall), Spark plan (no billing). Only App Distribution is used: no Analytics, Crashlytics or other product, and the app does not include the Firebase SDK or a `google-services.json`.
- Android app `Kinfall`, package `es.sebas1705.kinfall`, with the upload key's SHA-1 and SHA-256.
- App Distribution group `testers` (display name Testers). Testers are added by the owner (see [owner steps](owner-steps.md)); each tester gets an email invitation, accepts it on the phone and installs from the App Tester page or the Firebase App Tester app.
- Check the uploads: `firebase appdistribution:groups:list --project kinfall-sebas1705` (release count per group), or Firebase console > App Distribution > Releases.

## GitHub Actions (automatic on version tags)

`.github/workflows/distribute-android.yml` runs the same script on `ubuntu-latest`. It **activates once the repository has its GitHub remote (`Sebas1705/kinfall`) and the repository secret `DOPPLER_TOKEN` exists**; until then nothing runs.

- **Pushed tag `vX.Y.Z`:** a real upload to group `testers`. The first step checks that the tag is `vMAJOR.MINOR.PATCH` and equals `v` + `expo.version` in `apps/mobile/app.json` (the version name), and fails with a clear message before building otherwise. The version code is the commit count of the tagged commit, and the release notes are the commit subjects since the previous tag.
- **By hand (`workflow_dispatch`):** input `dry_run` defaults to true (build, sign and verify, upload nothing); `groups` defaults to `testers`.
- One repository secret, `DOPPLER_TOKEN`: a read-only Doppler service token for `kinfall/prd`. Permissions are `contents: read`, one run at a time (`concurrency: distribute-android`, never cancelled), actions pinned by major tag like `ci.yml`. The existing CI (`ci.yml`) never signs or uploads anything and does not run on tags, so tag only a commit of `main` whose CI is green.

### Releasing a new version

1. Bump `expo.version` in `apps/mobile/app.json` (for example `0.2.0`), commit, push `main` and wait for CI.
2. Tag that commit and push only that tag: `git tag -a v0.2.0 -m "Kinfall 0.2.0"` then `git push origin v0.2.0`.
3. Watch the run in Actions > Distribute Android; the release appears in Firebase console > App Distribution > Releases.

A tag that does not match `app.json` fails the run and uploads nothing: delete it (`git push origin :refs/tags/v0.2.0` and `git tag -d v0.2.0`), fix the version and tag again.

### v0.1.0 was uploaded by hand

`v0.1.0` (commit `9b6d2ce`, versionCode 108) was **already uploaded manually** on 2026-11-19 (see [First release](#first-release)). GitHub runs the workflow file **of the tagged commit** for a tag push, and at `9b6d2ce` the workflow is manual only, so pushing `v0.1.0` starts no run and uploads nothing: push it knowingly with `git push origin v0.1.0` so the tag exists on GitHub and the notes of `v0.2.0` start there. Do not move it to a newer commit: that would upload a second `0.1.0` with a higher version code. Pushing with `git push --tags` is fine for the same reason, but pushing tags one by one keeps every upload deliberate.

### Owner steps to activate it

Run these from the repository root in Git Bash, logged in to `gh` (as `Sebas1705`) and `doppler`. No token is printed: the Doppler CLI writes it straight into `gh`, which reads the secret from stdin.

```sh
# 1. Create the GitHub repository and add it as origin (choose --private or --public).
gh repo create Sebas1705/kinfall --private --source . --remote origin

# 2. Create a read-only Doppler service token for kinfall/prd and store it as the repository secret
#    DOPPLER_TOKEN without showing it (tr drops the trailing newline).
doppler configs tokens create github-actions --project kinfall --config prd --access read --plain \
  | tr -d '\r\n' \
  | gh secret set DOPPLER_TOKEN --repo Sebas1705/kinfall
gh secret list --repo Sebas1705/kinfall        # shows the name and date only

# 3. Push main (CI runs), then the tags (v0.1.0 starts no upload, see above).
git push -u origin main
git push origin v0.1.0
```

Optionally run Actions > Distribute Android > Run workflow with `dry_run` checked to prove the build and the secret work before the first tag that uploads. To revoke the token later: `doppler configs tokens --project kinfall --config prd` lists the tokens (name and slug, never the value), `doppler configs tokens revoke <slug> --project kinfall --config prd` revokes one (then create a new one as above).

## Rollback

App Distribution has no "promote" or "roll back" button; testers install whichever release they pick. To undo a bad build:

1. Ship a fixed build: revert or fix the commit, then run the script again. The new versionCode is higher, so testers update in place.
2. Or re-send an earlier good build: in Firebase console > App Distribution > Releases, open it and distribute it again to `testers`. An earlier release has a lower versionCode, so a tester who installed the bad one must uninstall first (saves are lost), or install a new build with a higher versionCode instead.
3. To stop new installs of a bad release, delete it in the console (Releases > the release > Delete). Testers who installed it keep it until they update.

## Not covered

No Play Store, App Store or iOS build is set up. Before any store listing: a Play Console app for `es.sebas1705.kinfall` (the id is fixed now), Play App Signing (upload this key), an AAB instead of an APK (`bundleRelease`), a privacy policy and the store texts.

### Runner memory (CI builds)

The GitHub runner has 7.9 GB of RAM. The native build (Skia, Hermes, React Native codegen, four ABIs in a release) used all of it: the debug job and the first `v0.2.0` run were shut down mid-CMake ("The runner has received a shutdown signal") with available memory down to about 190 MB. Both workflows now add an 8 GB `/swapfile2` (the image already uses `/swapfile`) after freeing disk, and the Gradle build is capped at two workers without project parallelism. A resource monitor in `ci.yml` prints memory, disk and load every 20 s during the debug build, to diagnose any future shutdown.
