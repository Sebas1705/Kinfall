# Run loop (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A complete, playable Expedition run: pick a starter, walk a three-zone node map, fight, recruit, evolve at shrines, lose creatures for good, beat three bosses (or die), with every step deterministic, auto-saved and resumable.

**Architecture:** The run is a pure, serialisable state machine under `src/sim/run/` that wraps the existing battle engine: one entry point `applyRunAction(run, action, content)` mirrors `applyAction`. Everything the player can do between and inside battles is a `RunAction`; the UI, bots, golden runs and saves all go through it. Presentation gains DOM screens (title, map, event, end) around the existing battle view; the phase-1 demo battle stays as `?mode=battle`.

**Tech Stack:** unchanged (TypeScript strict, Vite, Vitest, PixiJS 8, Playwright, GitHub Actions, Node 24, npm).

**Spec:** `docs/superpowers/specs/2026-11-14-creature-roguelike-design.md` (sections 3, 5, 6, 8, 11 bind this plan). Phase 1 plan: `docs/superpowers/plans/2026-11-14-engine-and-battle-slice.md` (its tests and rulings still hold).

This is plan **2 of 5**. Out of scope (later plans): items and relics (need battle hooks), move learning/forgetting, meta progression and codex unlocks, content growth and balance with bots (phase 3); daily run, share codes, result cards, replays, save export/import (phase 4); audio, PWA, polish (phase 5); Wander mode.

## Design calls made for this plan (mine, from spec §5; the owner may change any of them)

1. **Run shape.** 3 zones. Each zone has 6 choice layers (layers 0–5, two or three nodes each) plus a boss layer (layer 6, one node): about 21 steps per run (spec: ~20 nodes, 20–30 minutes). The player picks one node per layer; edges only go to the next layer.
2. **Node types.** `wild`, `elite`, `shrine`, `cache`, `mystery`, `boss`. Layer 0 is all wild; no elite in layers 0–1; at most one elite per layer; layer 5 always has a shrine. Other layers draw wild 50 / elite 15 / shrine 15 / cache 10 / mystery 10 (percent).
3. **Party and persistence.** Party of 1–3 creatures. HP carries between battles; focus refills and statuses clear. A creature that faints is **lost for the run** and leaves **1 soul**. If the whole party is lost, the run is lost.
4. **Encounters.** Wild: one creature from the zone's wild pool (not telegraphed). Elite: two creatures from the elite pool, telegraphed, +1 soul on win. Boss: the zone's boss with a scripted move cycle, telegraphed, +2 souls on win. Difficulty scales enemy **max HP only** (`hpPercent = 100 + 8 × global layer`; elites ×130/100, bosses per data); power scaling is a phase 3 balance item.
5. **Recruiting.** After a wild win the defeated creature may join at half HP; with a full party the player must pick one member to replace (the replaced one just leaves, no soul).
6. **Shrine.** Choose one: **Rest** (heal 50% of max HP to every living member), **Evolve** (spend the species' soul cost on one member that can evolve), or **Leave**. **Cache:** +2 souls and heal 25% max HP to every living member. **Mystery:** *Open* (seeded coin flip: +3 souls, or the first living member loses 20% of max HP but never drops below 1) or *Leave*.
7. **Starters.** The player picks one of three starters (ember, thorn, tide species).
8. **Score** (integer): `zonesCleared·1000 + bossesBeaten·250 + elitesBeaten·100 + nodesCleared·20 + souls·10 + sum over living members of floor(100·hp/maxHp)`.
9. **Saves.** Auto-saved after every run action (so also after every battle turn); one slot in `localStorage` with a checksum; the UI says saves live in this browser and clearing site data loses them.
10. **Demo page.** The phase-1 battle page remains reachable at `?mode=battle` (used by the existing e2e specs and as a test bed); the default page is now the title screen.

## Global Constraints

- Simulation code under `src/sim/` and `src/content/` must not use `Math.random`, `Date`, `performance.now`, `Math.sin/cos/pow/exp/log`, or any floating-point maths whose result could differ between engines: integers only, seeded PRNG only (spec §3). The AST guard `tests/sim/determinism-guard.test.ts` already scans `src/sim` (recursively), `src/content`, `src/art` and `src/view/demo.ts`; new sim code must live under those paths.
- Same seed + same player inputs = same outcome on any browser or device (spec §3, §6). The phase-1 golden hashes in `tests/golden/battle.golden.json` must NOT change.
- Initial download under ~2 MB (`npm run size`); later assets lazily loaded (spec §3).
- Saves live in the browser and the UI must say clearing site data loses them (spec §3).
- Keyboard, mouse/touch and gamepad; colour is never the only carrier of meaning; honour reduced motion; no flashing effects; scalable text (spec §3, §8).
- Spanish and English from day one; every UI string in both languages, Spanish gender-neutral for creature names (existing deny-list test) (spec §3, §8).
- Original names, art and layouts; five elements `ember, thorn, tide, gale, umbra` (spec §5, §11.5).
- Web only; no server, accounts or tracking; permissive dependencies only; project code MIT.
- No `git push` and no deployment in this plan; no `playwright install` locally (e2e on Edge; Firefox/WebKit only in CI).
- Commit messages: short, imperative, English, no trailers.

## Review Focus

1. A run save that is corrupted, truncated, from another version, or tampered with a valid checksum (inconsistent phase: a battle with no living player creature, party over 3, negative souls, a node id missing from the map, `winner` inconsistent with fainted teams) must be rejected with a clear message and never crash or soft-lock the page (Tasks 8, 9, 13).
2. Illegal run actions (wrong phase, a node that is not available, recruit with a full party and no `replaceIndex`, evolving without enough souls or without an evolution, any action after the run ended) must be rejected with the state unchanged, never throw (Tasks 5–7).
3. Blocked or full storage (private window, quota exceeded) must not break play: a failed autosave shows a non-blocking warning and the run continues (Tasks 9, 13).
4. A run reloaded at any battle turn must resume to the same state and reach the same final outcome as an uninterrupted run (Tasks 10, 14).
5. The map screen at 320 px with long Spanish node names and 150% text must not overflow, must be fully reachable by keyboard, and node types must be told apart without colour (Tasks 12, 14).
